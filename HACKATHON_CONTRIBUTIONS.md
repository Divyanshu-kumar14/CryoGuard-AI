# Hackathon Contributions

This file records what was built, where it lives, and what evidence exists for
each claim. It is deliberately narrower than the README: the README explains the
system, this file separates *implemented*, *simulated*, *live-verified*, and
*not validated on hardware*.

## Building period

Every commit in the repository history is dated **2026-10-30** or **2026-10-31**
according to `git log --format='%h %ad %s' --date=short`. No earlier development
history, imported codebase, or back-dated work is claimed. The Phase 2 hardening
work described at the bottom of this file was performed on the
`fix/reliability-hardening` branch after the committed baseline
`c2682064b0edcf79c52d95fdc4fcaf933c8b9cc0`; it hardens existing modules rather
than adding product features.

## What is simulated

Every physical or infrastructure interaction in this repository is simulated
unless the section below explicitly says otherwise:

- **Camera and scenes** — four clips generated by `scripts/make_sim_fixtures.py`;
  there is no camera, UV excitation, long-pass filter, or tracer in the loop.
- **PLC** — Modbus-TCP loopback simulator (`src/cryoguard/sims/plc_server.py`);
  the valve, limit switch, pressure register, and fault coil are simulated.
- **BMC** — Redfish HTTP mock (`src/cryoguard/sims/bmc_server.py`); responses
  carry `Oem.CryoGuard.simulated = true`.
- **NVML** — `FakeNvml` in the demo. The real `pynvml` path exists but was not
  exercised on a GPU.
- **Scheduler and checkpoint storage** — in-process Slurm mock and local
  checkpoint directory, not a production scheduler or shared filesystem.
- **Telemetry** — replayed from scenario YAML, not sampled from a CDU.
- **Thermal model constants** — design assumptions, not measurements.

## Live API evidence

- **SAM 3.1:** authenticated hosted request and mask decoding described above.
- **Muse Spark Open:** live inference through Baseten; the proof log records
  model id, provider, timestamps, latency, token counts, and (after hardening)
  finish reason, response size, schema validity, and failure category.
- **Nothing else is live.** No real DNS, BMC, PLC, Slurm controller, GPU, or
  camera is contacted by the tests or the benchmark.

## Not validated on physical equipment

- Camera calibration, fluorescence contrast, tracer behaviour, and spill
  physics under real lighting.
- Real GPU temperature sensor semantics. `RealNvml` reads
  `NVML_TEMPERATURE_GPU`; it is **not** claimed to be a hotspot or junction
  sensor unless the device exposes that measurement.
- Real valve travel, seal leakage, limit-switch behaviour, pressure transducer
  accuracy, and sensor disagreement rates.
- Real BMC authentication, `ForceOff` timing, and `PowerState` readback.
- Real scheduler cordon/requeue behaviour and checkpoint durability.
- Thermal time constants, watchdog thresholds, and false-trip rates at scale.

Any statement about physical safety, real leak detection accuracy, or data-centre
readiness beyond the simulated evidence above is unsupported by this repository.

## Phase 2 hardening (this branch)

The hardening branch changes existing modules only:

- Watchdog: typed GPU observation with honest backend provenance, multi-channel
  frozen-sensor corroboration, configurable sustained-load hysteresis, and
  non-emergency `HEALTH_DEGRADED`.
- Watchdog fallback: independent BMC path wired into the composition root,
  verified `Off` readback, latched duplicate triggers, propagated task failures.
- Hydraulics: AND-policy between limit switch and pressure witnesses,
  `SENSOR_DISAGREEMENT`, confirmation reads and hysteresis; isolation is never
  reported from stem closure alone.
- Power: an accepted BMC request is never treated as a verified power-off.
- Leak source: observed spill centroid, candidate bbox centre, estimated source,
  configured fitting, and independent ground-truth source are separate
  quantities with explicit uncertainty.
- Muse: provider metadata, truncation classification, compact repair, strict
  schema validation, deterministic fallback, and an auditable health summary.
- Benchmark: synthetic title, independent source ground truth, fault-injection
  matrix counted separately from scenario metrics, and a generated README block.

See the final engineering report in the pull request for commands, pass counts,
and remaining risks. This file makes no claim that the hardening work was part
of the original hackathon submission; it is post-submission reliability work.
